文本乱码修复

    
从 Windows 记事本或 Excel 导出的 TXT / CSV 常是 GBK 编码，在 Mac 或网页里打开就是一片乱码。这里可以自动识别编码并转成 UTF-8。

常见问题

  

    

      文件真的不会被上传吗？
      
不会。所有解析和转换都在你浏览器的 JavaScript 里完成，页面没有接收文件的服务端接口。断网状态下功能依然可用（首次加载完页面后）。文档里的图片会被转成内嵌的 base64，同样只存在于本机内存。

    

    

      Word 转出来的排版和原文一样吗？
      
段落结构、标题层级、列表、表格、图片这些语义信息会保留，但页码、页眉页脚、分栏、文本框、艺术字、复杂公式这类版式信息不会。这是 .docx 转 HTML 的通用限制，导出前请对照预览确认。

    

    

      为什么 Markdown 转 Word 的排版比较朴素？
      
生成的 .docx 使用标准样式（宋体/等线、11pt 正文、标题分级）。这样做的好处是 Word、WPS、Pages 都能正常打开和二次编辑，代价是不会复刻某个模板的视觉设计。

    

    

      大文件会不会卡住？
      
10MB 以内的 .docx 通常在 1 秒内完成。特别大的文件（几十 MB 或含大量高清图片）会占用较多内存，浏览器可能会短暂无响应，建议先压缩图片再转换。

    

    

      能私有部署吗？
      
可以。项目是 MIT 协议的纯静态站点，npm run build 之后把 dist/ 目录丢到任意静态托管（Cloudflare Pages、GitHub Pages、Nginx、对象存储）都能跑，不需要服务器和数据库。
